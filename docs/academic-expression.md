# 学术表达润色

`academic-expression` 是 PaperKnow 自有的服务器写作附加技能。论文章节、综述章节、普通文稿正文和摘要在现有 Agent 执行中加载它，按组织论述、表达自检、局部润色、完整候选提交的顺序完成一次写作。它不安装外部 Humanizer，不生成检测分数，也不创建另一项付费任务。提纲、方法建议、选题、问卷、补充资料完整性检查与科研工具保持原阶段组合。

技能要求减少空泛背景、同义反复、机械衔接和夸饰，保持专业术语、直接引语、数据、公式、代码、表格、引用标记及证据边界。文风要求不能改变研究实施状态，不能把计划、假设或缺失数据改成已验证结果。提交仍由原结构、实际读取来源与篇幅校验冻结；没有为风格增加强制重试或延长费用预算。

全文审校组合也加载该技能，但保持只读：模型只能在主任务现有 JSON 契约的 `language_expression` 类别下返回实际原句和具体建议。服务端严格校验章节与逐字原句，前台在原有生成检查窗口显示“学术表达”。现有审校预算不足或服务不可用时，沿用部分审校状态，不能丢弃已保存正文。

本地表达检查仅定位重复段首衔接和部分笼统确定性开头，作为信息提示，不进行字符串替换、自动删词或生成拦截。代码围栏、公式、表格、引用块、引语、标题和待补充标记排除在表达匹配外；位置使用原文 UTF-16 偏移。普通术语重复、编号步骤、统计量与研究限制不会仅因词频而被改写。检查结果不代表文字来源或学术质量认证。

已有保存稿件不会被后台静默改写。新生成的单元使用新技能；继续生成仍跳过已经完成的单元。原积分、专项套餐优先顺序、一次成功结算、取消与失败释放规则均保持原状。
