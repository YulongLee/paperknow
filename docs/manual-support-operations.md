# 人工售后与资料请求处理

本流程适用于通过工作台“帮助与反馈”提交的订单与退款、个人信息请求。管理员在后台“反馈”中按分类或订单号搜索，处理状态仅表示反馈进度；保存状态和备注不会退款、冲正权益、注销账户、删除资料或通知用户。必要时通过用户主动提供或账户绑定的有效联系方式人工联系，不要求用户提供密码、验证码、支付凭据或非必要的研究正文。

## 订单与退款

1. 取得用户提交的订单号；如果有订单号，提交时服务端只允许关联当前账户的订单。没有订单号的请求仍可提交，由支持人员进一步核对。
2. 在后台查询订单及其账户，核对订单状态、实际收款渠道、金额、支付记录、已发放权益与使用记录；有疑问时联系用户并核对商户平台。不要仅根据用户截图确认收款或退款。
3. 按公布的退款规则确定是否退款、金额和权益处理方式；在商户平台通过已有授权人工操作，并核实渠道实际结果。操作前须确认权限及是否存在已消费权益；本站目前没有自动退款或权益冲正，不可仅修改反馈状态代替这些操作。
4. 在后台订单的“退款记录”中登记已核对的渠道流水、金额及备注；同一渠道流水不能重复登记，累计金额不能超过原订单金额。该记录仅由管理员填写，不会调用或验证渠道、改变订单状态、调整权益或通知用户；登记后不能直接修改，发现错误须升级负责人核对。反馈备注还应记录权益核对状态和经办人，不记录支付密码、令牌或私人研究内容。只有实际退款和相应权益处理完成后才能说明退款已完成；如存在退款后权益处理无法完成的问题，保持处理中并升级处理。
5. 人工告知用户处理结果；后台反馈备注不会自动发送。对账时将商户平台实际流水与站内订单、权益及退款记录逐项核对。

## 个人信息请求

1. 及时受理用户对个人信息查阅、更正、删除以及账户注销的具体请求，不因产品没有自助注销按钮拒绝申请；核验申请人与账户归属，最小化收集信息，不要索取密码、验证码或完整研究正文。
2. 核对请求涉及的账户记录、原件、生成文件及其存储、备份范围和法定保留义务。按适用法律与实际能力制定处理方案并回复用户，不以退出登录或单次文件删除冒充所有副本清理完成。
3. 当前没有完整账户注销和批量清除全部数据的产品能力；不能将反馈标记“已处理”或发送通知当作注销、删除完成。对超出已有安全功能的请求，应及时升级至负责人，建立并验证可执行的人工处理和留存方案，按适用时限推进、告知进展，并在实际执行后如实答复；依法必须保留的记录应说明范围与理由。
4. 仅记录必要的身份核验方式、请求类别、处理范围、结果及时间，避免将密码、证件影印件和私人研究正文复制到备注。依法需要留存的数据按要求限制使用和保护。
