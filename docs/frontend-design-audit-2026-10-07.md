# PaperKnow 前端设计全面检查

检查日期：2026-10-07。对象：本地当前版本，Git 基线 e325823。本次只检查并生成报告，没有修改业务代码或真实用户数据，也没有执行支付、兑换、归档或删除。

## 结论

蓝白配色、功能分组、卡片与列表布局已有完整产品框架。项目、成果、任务、账户、设置和帮助都已有入口，手机成果页也已使用卡片布局，不能再按旧截图判断为只有几个空功能卡片。

仍有优化空间，优先改善阅读、操作路径、输入保护与跨页面一致性。当前可以继续作为本地体验产品测试；视觉完整不代表可开始收费。真实账户、AI、在线检索、云同步和支付/权益尚未接入，需与前端设计问题分开验收。

## 检查范围与通过项

- 桌面浏览器检查 21 个工作台主要路由：概览、项目、成果、任务、写作、文献、修改、检测、PPT、科研、排版、更多、会员概况、会员购买、套餐、充值、兑换、设置、帮助、账户、订单。
- 另外检查官网、一个已有项目详情和一个已有自建测试材料的查重报告。未新建或删除持久化测试记录。
- 21 个工作台主路由都呈现标题及内容；初始桌面实际 CSS 宽度 1256 下没有页面整体横向溢出。
- 复测实际 CSS 390×844 手机宽度，21 个工作台主路由、官网和已有报告没有文档整体横向溢出。这不代表所有内部滚动区域、软键盘或任意长内容都已验收。
- 常见桌面尺寸复测使用实际 CSS 1280×900；浏览器有缩放，尺寸以页面实际测量值为准。
- 扫描主页面表单标签关联，未发现缺少 label / aria-label / aria-labelledby 的输入；该扫描不覆盖所有动态弹窗和完整无障碍行为。
- 语法检查通过；现有 91 项自动化测试全部通过。浏览器采集的 warn/error 为空。并不意味着完整上线流程已验证。
- 菜单已有 Escape 关闭，弹窗使用原生 dialog；未将这些已存在的能力误报为缺失。

## 优先级问题与建议

| 优先级 | 发现与证据 | 用户影响 | 建议及验收 |
| --- | --- | --- | --- |
| P1 | 新建项目输入后点击关闭，弹窗直接关闭；重新打开项目名称为空。使用临时文本复现，未保存项目 | 用户研究说明和配置可能因误关丢失 | 弹窗统一增加继续填写/放弃/保存草稿；关闭按钮、遮罩、Escape 行为一致；没有修改时直接关闭 |
| P1 | 手机侧栏收起后仍有 17 个导航/账户控件可聚焦；从菜单按钮 Shift+Tab 实际聚焦到屏幕外的账户按钮。侧栏没有 inert，菜单按钮没有 aria-expanded | 键盘及辅助工具会进入不可见区域，操作状态不可知 | 收起侧栏时 inert；展开时同步 aria-expanded；管理焦点、背景可交互性及关闭后的焦点恢复 |
| P1（上线前） | 会员价格 10/20/40 仅为参考数值，无明确计价单位；套餐字数、有效期、退费和额度规则仍未确认 | 用户无法比较实际价值；不应作为可支付商品 | 确认服务目录和统一计量规则，在商品卡与确认页显示完整周期、字数、次数和有效期；当前继续标预览并禁用支付 |

| P2 | 写作页在实际 1280×900 下主按钮顶部约 y=1229；390×844 下约 y=1317。可选写作要求默认展开 | 用户填写题目后仍需滚动才能开始，主任务被可选字段稀释 | 首屏只保留题目、学段和必要配置；可选项默认收起；桌面可设表单操作栏、手机底部操作栏，且不能遮挡正文/软键盘 |
| P2 | 报告页切换为另一套侧栏、品牌标语和“研”头像，本地昵称 test 不再显示；“重新预检”和工作台“论文查重”用词不同 | 进入报告后像换了产品，项目和成果上下文被打断 | 报告复用同一外壳或统一沉浸式报告页，保留项目返回、账户资料、检测类别和当前范围；“重新检测”命名统一 |
| P2 | 项目详情中同时出现 ISO 日期含 T/Z、2026/10/4、10/5 和“本地保存” | 记录时间难比较，内部数据格式暴露给用户 | 所有保存时间统一格式化，未知时间明确“时间未记录”；展示日期时保持同一时区 |
| P2 | “降重复率 / 论文降重”、“导师修改 / 导师意见修改”、“AI 研读 / 文献研读”及待上线/待开放/待接入/流程体验混用 | 用户不确定是否同一工具，也不确定当前能做什么 | 建立名称与状态词表。名称全站一致；状态分“本地可用 / 在线未开放”，另行注明模板、手动编辑或真实 AI 的处理方式 |
| P2 | AI 写作、降 AI 率等入口与主按钮较显眼，实际能力说明常位于较小文字中；页面整体已声明未接入 | 用户可能在操作后才发现只能用模板或手动编辑 | 在动作附近短句说明当前输出，例如“生成大纲模板”；保留品牌功能名，并在入口显示当前能力。避免把关键边界仅放页尾 |

| P2 | 概览最近成果使用 role=tab，但所有 tab 都 tabIndex=0，未关联 aria-controls；静态检查没有对应方向键处理 | 视觉分组与辅助工具预期不一致 | 真正实现选项卡键盘与面板关联，或作为普通筛选按钮使用 aria-pressed；不要只加角色而不实现行为 |
| P2 | 成果与任务操作、多个过滤入口高度不足 32px；手机页面虽然不溢出，点击目标仍偏小 | 容易误点相邻的编辑/导出等操作 | 为手机操作提供约 44px 的点击区域与适当间距；低频操作收进“更多”，主动作明确 |
| P3 | 工具布局逐页追加，工作台主模块约 59KB、hub.css 约 121KB 未压缩，并加载原报告与旧工作台样式 | 不是已证实的加载故障，但维护和样式覆盖风险增加 | 分离共同设计变量与页面样式，抽出表单/步骤条/状态/列表组件；建立按页截图回归，再衡量加载性能 |

| 帮助与反馈 | 帮助搜索、指南及本地反馈范围较清楚 | 上线后接真实工单状态、回复和运营联系入口；本地导出不等于已提交 |

## 推荐实施顺序

1. 输入保护与手机导航焦点：先防误操作和不可见焦点。
2. 统一字号、灰色、按钮、名称和状态标签；规范日期与账户展示。
3. 缩短写作/检测/PPT 表单路径，统一桌面与手机操作栏。
4. 统一报告外壳、项目上下文及从报告到修改稿的衔接。
5. 确认价格和权益，再完成真实账户、支付、队列、AI 与云端服务；最后验收收费流程。

每一阶段均以实际流程验收，不用“多一些卡片”代替效果验证。没有用户行为数据，本报告不能给出真实转化率或声称某布局一定提高付费率。
