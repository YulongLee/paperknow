# PaperKnow 管理后台与统一工作台

管理后台地址为 `/admin.html`。普通用户始终进入 `/workspace.html`，旧 `/service.html` 链接会跳转至主工作台对应的账户内容页。账户项目、任务、成果、用量与反馈沿用原服务端数据库，本地草稿不迁移、不覆盖，也不自动同步。

## 管理员身份

仅在服务器环境配置中设置 `PK_OWNER_EMAIL`。该邮箱必须通过邮件验证码完成注册、登录或重置密码，或者已经拥有经验证的邮箱身份，才能自动获得管理员权限。仅修改昵称、请求参数、前端缓存或未验证的邮箱资料不会授予权限。没有默认管理密码。

已有未验证账号可使用 `/auth.html?mode=login&method=code&verify=1&next=%2Fadmin.html` 完成验证。验证码成功后沿用原用户 ID 和资料；历史未验证密码会依既有登录规则失效，之后可以重置密码。管理员从首页账户菜单、主工作台账户菜单进入后台；普通用户不显示入口。

管理员 HTML 在服务器校验会话，访客重定向登录，普通用户返回 403。每个管理 API 再次校验数据库中的管理员角色，不依赖隐藏按钮。后台不开放在线提权或密钥修改接口。

## 首期功能

- 数据总览：用户、项目、文件、任务、成果、待处理反馈及真实每日新增记录。
- 用户管理：查看与搜索账号、验证状态、角色、项目及任务数量。
- 任务管理：查看执行状态、错误信息并取消排队或执行中的任务；不可取消已结束任务。
- 成果管理：查看成果元信息，不批量暴露论文正文。
- 反馈管理：未处理、处理中、已解决状态及内部处理备注。
- 订单与用量：查看已有记录；支付尚未接入，不展示虚构收入。
- 系统设置：查看短信、邮件、存储、AI 的实际配置状态，调整已有 AI 模型名称与启停。
- 操作日志：记录管理员身份确认、任务取消、反馈处理和模型调整。

列表默认每页 20 条，最多 50 条，搜索与筛选使用服务端参数验证。密钥、验证码、密码摘要及任务原文不进入管理列表。

## 发布与验证

配置示例不包含真实邮箱或服务密钥，生产值仅写入 `/etc/paperknow/paperknow.env`。部署前备份数据库及配置；只重启 `paperknow.service`。数据库新增管理日志表和反馈处理表，原反馈数据和用户关联保留。

`npm run test:auth` 验证身份及既有服务行为；`npm run test:admin` 验证管理员权限、邮箱所有权、接口分页及操作、入口跳转、后台交互和统一工作台。发布脚本同时执行两组测试。

本次本地全量回归为 248 项：244 通过，4 项失败均已在上一线上版本 `1db2c8e` 的独立导出中复现，属于旧写作导览、会员入口计数和偏好字段断言；本次未修改这些功能。登录及后台专项检查通过，发布时会在服务器隔离构建环境再次执行。
