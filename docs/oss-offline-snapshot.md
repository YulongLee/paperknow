# OSS 对象离线快照与隔离验证

这是手工、默认关闭的运维工具；它不会创建云资源、写入或删除 OSS，也不会替换运行中的数据库或对象。**当前没有配置自动执行、异地备份或生产恢复，不得将代码存在视为灾备已启用。**

工具读取一次已完成的 `deploy/backup.py` 数据库快照，以该快照中的 `files`（OSS 原件）和 `artifacts`（`ready` OSS 成果）为清单。逐个核对项目桶、原账户路径、长度和 SHA-256 后保存到用户明确指定的独立目录；上传中、删除中或原件删除待完成时拒绝备份。缺失或变化的对象会使本次备份整体失败，不发布不完整目录。数据在数据库快照创建后新增、删除或修改仍可能造成快照和 OSS 时点不一致，删除导致旧对象无法读取时应重新规划一致性快照，而非忽略错误。

## 运维前提

- 使用此前完成且无活跃 WAL/journal 的 SQLite 快照，不能使用线上数据库文件或将它更改为活动数据库。先运行 `deploy/verify_snapshot.py`，并确认快照完整可读。
- 选用与快照不同目录的**独立受保护备份卷**，由运行账号独占，目录所有者为运行账号且权限为 `0700`；全部路径不能包含符号链接。禁止把结果放进源码、应用当前版本、配置目录或运行中的数据目录。预先检查空间，容量需足以容纳所有对象及一次隔离副本。备份根目录内的临时文件及最终文件分别为 `0700` / `0600`。
- 将整个卷加密，限制访问和传输；清单包含私人对象键和账户标识。文件权限不等于静态加密，传输或异地保存需要独立的加密和授权控制；不要将备份上传 Git，不在工单中展示清单或文件正文。
- 备份进程需要在受保护的进程环境提供现有 `PK_OSS_BUCKET`、`PK_OSS_ENDPOINT`、`PK_OSS_REGION`、`PK_OSS_PREFIX`、`PK_OSS_ACCESS_KEY_ID`、`PK_OSS_ACCESS_KEY_SECRET`，使用仅列/读取目标对象的最小权限凭据。不要把密钥放命令行、日志或聊天；请由运维按现有安全环境注入，不要复制用户的线上凭据。
- 使用项目服务器指定 Node 运行时与该版本依赖；仅经批准的运维人员在合适窗口运行。不要同时改变 OSS 对象或处理删除任务；工具没有冻结业务或创建跨服务事务。

## 显式操作

以下路径只是示例，先准备并确认私有目录、备份卷及必要权限：

```sh
node deploy/oss-snapshot.mjs backup /path/to/completed-db-snapshot /path/to/private-independent-backup-root
node deploy/oss-snapshot.mjs verify /path/to/completed-db-snapshot /path/to/private-independent-backup-root/oss-snapshot-UUID
```

备份成功输出新目录与对象数量；失败会清理本次未完成目录，不输出密钥、对象名或上游报错。验证只需要 `PK_OSS_BUCKET` 和 `PK_OSS_PREFIX`（无须 OSS 密钥或网络），会核对数据库快照哈希和对象清单，再复制到临时目录验证所有大小及哈希，之后删除临时副本。须保留原 SQLite 快照与该 OSS 快照配对，保管数据库快照中可能包含的环境配置。

本工具不备份客户端安装包、健康探针、没有数据库索引的孤儿对象、其他 Bucket、历史对象版本或 OSS 配置；不证明存储目标的异地独立性、加密、第三方留存、完整用户业务可恢复或真正的 OSS 恢复。隔离复制验证也不等于恢复到新账户或真实访问验证。尚须制定并在授权隔离环境实际演练新库和新桶的完整恢复、账户与文件关联核对、权限与灾备时效；不要指向生产目标做覆盖恢复。

局部测试：`node --test tests/oss-snapshot.test.mjs`；仅使用合成数据库和模拟对象存储，无真实云访问。
