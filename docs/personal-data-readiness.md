# 个人信息请求：现状与处理范围

本文件供运营和研发核对，不代表注销或删除功能已经实现。没有自助注销入口，不等于可以拒绝用户提出的注销或个人信息请求。现有反馈入口仅负责收集请求，状态变更不会删除数据或通知用户。

## 范围盘点

- 账户：`users`、`auth_identities`、`sessions`、身份验证记录；验证记录不一定直接通过用户 ID 关联，应同时核对身份地址以及合法保留期限。
- 研究内容：项目、草稿、原件、成果、修改版本、任务输入和结果，以及论文、提纲、章节历史、上传初稿对象、文献标注等关联表。部分表只通过任务、论文或文件 ID 关联，不能只按 `user_id` 搜索。
- 云文件：`files` 和 `artifacts` 保存存储元数据，实际对象可能位于 OSS；删除数据库记录并不等于删除云对象。还须核对上传、删除或生成中的任务与重试队列。
- 支付与运营：订单、支付记录、积分流水、权益、退款登记、反馈及后台审计。需要逐项确定法律要求与保留期限，不能将全部财务数据一概归入必须留存，也不能为方便删除擅自移除审计保护。
- 副本与外部处理：数据库快照、待建立的加密云文件备份，以及文档解析和模型等第三方处理链路；应按实际服务协议核实其保留与删除机制。恢复备份时应防止已经处理的数据重新上线。
- 浏览器：当前仍存在访客本地编辑以及按账户隔离的本地编辑缓存，旧共享键未自动迁移；部分本地报告保存在 IndexedDB。云端处理无法自动清除用户其他设备上的浏览器数据，也不能保证在重新登录后替用户清除历史缓存。

## 操作和边界

1. 核验请求人对账户的控制权和具体请求，避免收集密码、验证码、完整研究正文或不必要的证件。明确账户、关联文稿与文件范围，以及用户是否需要先下载资料。
2. 先冻结会继续写入相关数据的任务，并在隔离副本上核对关联与待处理状态；明确哪些记录因法律义务需要限制处理和保留，以及后续到期机制。切勿通过直接删除账户行、关闭外键或触发器、删除整桶来处理。
3. 对具体的云对象、数据库内容、外部处理及备份建立可审计的清单与实际执行记录。仅在每个适用范围完成并核验后如实反馈；有尚未处理的范围应说明并继续升级处理。
4. 目前产品没有完整的用户注销与全链路清理工具，也没有针对用户数据的可验证备份清理或恢复抑制机制。应继续受理并升级，不能因反馈状态变更而标记注销/删除完成；尚不具备可靠自动执行能力时，运营负责人须组织建立并验证人工方案。

## 开发优先级

1. 建立只读、最小权限、需要身份复核且可审计的数据范围核对工具，按账户和关联关系呈现数量及状态，不输出研究正文或密钥；数据分散在未直接引用账户的子表中，单纯统计 `user_id` 不能作为完整清单。
2. 在隔离环境验证停止任务、云对象删除、数据库按依赖关系清理及失败恢复，明确合法留存与期限。现有章节历史、消费预占与积分流水存在禁止删除触发器，必须按数据类别设计可审计、可恢复的机制，不能直接跳过保护。
3. 明确保留策略和已处理请求在备份恢复时的再执行/抑制机制，并分别核实用户设备缓存与第三方数据处理方式。发布前需要一次覆盖数据库、云文件与隔离恢复的完整演练。

## 统一云账户的最小安全改造

用户最新要求使用 OSS 保存用户文件，不新增本地历史导出入口；下列迁移与保护事项仅供研发规划，不改变或删除现有设备数据。生产环境在 OSS 不可用时不应静默将新原件写入服务器数据库；历史 SQLite 原件必须保留读取兼容，待核验后安全迁移。

1. 访客可浏览首页、功能介绍与帮助；进入写作、文献库、检测、改写、演示、排版和科研工具的编辑保存或 AI 操作前要求登录，并在登录后返回原功能。区分未登录与账户服务不可用，服务错误不能判定成访客或切换存储。已打开的编辑页遇到账户变更、登录过期或断网时保留未提交内容，提供导出和重新登录，不应显示已保存云端。
2. 登录后新建文稿应先建立账户草稿，在内存中编辑并以版本号保存；保存失败不得覆盖或伪称成功。当前 `dist/workspace/writing.mjs` 仍有“草稿已自动保存到当前浏览器”分支，`state.mjs` 也有本地回退，登录门槛本身不足以实现该目标。现有账户编辑器已有版本冲突和失效提示，应在此基础上统一其他编辑入口，而非另建一套覆盖机制。
3. 迁移时区分按用户隔离的 `paperknow-drafts:account:<编码用户ID>` / `paperknow-local-tasks:account:<编码用户ID>`、访客后缀 `:guest` 和无后缀旧共享键。只允许当前账户读取匹配的账户缓存；访客与旧共享内容不能推断所有权，须由用户逐项选择并明确导入目标账户，绝不可自动认领。IndexedDB 历史报告和其他设备的数据同样不能假定属于当前账户。
4. 导入前展示范围、文件/条目和目标账户，按内容校验和持久化任务避免重试产生重复，并在服务器成功写入、回读核对后报告结果；本地原件默认保留，失败、退出和账户切换不删除或覆盖。`POST /api/workspace/drafts` 支持以账户和 `clientKey` 进行幂等创建，内容变更复用同一键会返回冲突；项目 ID 需要按目标账户重新关联。
5. 可暂停新建访客草稿，但先提供本机历史内容的安全查看和导出回退。当前 `backup-service.mjs` 的 `currentBackup` 只读无后缀旧键，并未包含访客及账户后缀的草稿/任务，不能称为完整本地备份；且 IndexedDB 的报告和来源有独立存储。应先设计版本化备份格式和读取范围，在多账户设备上避免列出或导出其他账户的隔离缓存，再逐类提供迁移与导出。
6. 用至少两个账户与访客缓存验证隔离、归属不明记录确认、幂等重试、部分失败和回读、断网、账户切换、会话过期、跨设备冲突及资料附件；保留可恢复的原始内容。仅隐藏“本地工具”或“本地草稿”字样会掩盖仍然存在的功能，也可能让历史内容不可见。
