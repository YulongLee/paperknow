# PaperKnow 运行监控

本次新增管理员专用的「运行监控」页（`/admin.html#monitoring`）。普通账户和匿名请求不能读取指标或修改阈值；API 会重新查询数据库中的管理员角色。

## 采样与保留

- 服务进程启动即采样，默认每 60 秒一次，与管理员是否在线无关；后台可以调整为 30–600 秒，也可以暂停。
- 采样最多保留 1,440 条，告警变化最多保留 200 条。页面返回最近 100 个趋势点和 30 个告警变化；表格限制高度，不会无限拉长页面。
- 项目发布版本、备份和缓存容量每 15 分钟缓存一次。固定启动目录由服务器代码提供，后台不能修改路径。扫描跳过符号链接，并限制扫描条目和耗时；未完整遍历时标记为「至少」，而不是误报精确容量。
- OSS 实际读写健康探测最多每 15 分钟执行一次；配置完成与探测通过分别显示。探测采用项目专用小对象，具体私有读写、校验和补偿删除由存储模块负责。
- 采样失败时保留上一次有效记录，明确展示采样错误及旧数据状态，不会将采样失败显示为健康。
- 告警仅在后台展示，不会自动删除文件、关单、释放积分或发出邮件/短信。

## 指标

1. 整台共享服务器：所在卷可用容量、磁盘使用率、可用内存、每核心负载。
2. PaperKnow 本身：进程 RSS、堆内存、进程存活时间、数据库及 WAL 容量。
3. 业务任务：排队与执行中数量、长期未更新任务、最近 24 小时完成/失败样本与失败比例。
4. HTTP：最近 5 分钟 5xx 比例与 P95 响应耗时。请求样本仅存状态和耗时，不保存 URL、参数、正文、用户身份；内存最多 10,000 请求，进程重启后重新计数。
5. 结算与订单：持有中的积分/权益预占、长期未结算预占、待支付数量、已过期但仍待支付订单。这些指标不等于向支付渠道完成对账。
6. 生成文件：对象存储最后成功时间及失败状态；生成文件 `failed` 状态数量（存在产物表时）。

失败率与响应告警必须先达到配置的最少样本数；没有调用样本显示「暂无」，不视为错误率 0%。

Linux 内存指标优先使用固定 `/proc/meminfo` 的 `MemAvailable`，避免将可回收缓存全算成内存不足。其他系统使用操作系统报告的可用内存。

## 启动接线

```js
import {createMonitoring} from './backend/monitoring.mjs';
const monitoring=createMonitoring(db,config,{
  databasePath:dbPath,
  volumePath:'/opt/paperknow',
  directoryTargets:{
    releases:'/opt/paperknow/releases',
    backups:'/opt/paperknow/backups',
    cache:'/opt/paperknow/build-home/npm-cache'
  }
});
config={...config,monitoring};
// 此时 config.storage 已初始化；所有 API 使用同一个 monitoring 对象。
monitoring.start();

// 每个本站请求结束后只记录以下两项：
monitoring.observeRequest({statusCode:res.statusCode,durationMs:elapsedMs});

// 关闭时先停止采样，再关闭数据库。
await monitoring.stop();
```

## 管理 API

- `GET /api/admin/monitoring`：设置、最近有效采样、采样器状态、有界趋势和告警变化。
- `POST /api/admin/monitoring/settings`：提交当前 `version` 和允许的设置。支持乐观并发检查，审计日志只记录设置版本与变更字段。
- `POST /api/admin/monitoring/sample`：只接受空对象，手动触发一次采样，最多每 30 秒一次。仍遵守 OSS 和目录 15 分钟探测缓存。

设置只接受启停、周期和既定数值阈值；拒绝任意 URL、路径、通知目标、未知字段和不合范围的数据。

## 运维边界

本机进程彻底退出时不能依赖进程内部监控自行报警。腾讯云侧还应独立配置实例磁盘/内存告警、HTTPS 存活探测与必要的通知渠道。后台明确提示这点；本功能没有自动开通或变更其他云服务。

磁盘与内存属于共享主机，不能据此认定占用全部来自 PaperKnow。项目目录容量另行统计；清理只能根据专门的版本保留策略处理，不应删除数据库、配置、交易记录或其他服务文件。

本实现不自动处置未结算预占或待支付订单，避免误操作账务。应查看具体任务与订单后，通过独立的补偿/对账流程处理。

## 验证

新增测试覆盖管理员隔离、阈值与并发校验、自动采样、暂停与停止、采样错误回退、OSS 缓存与错误脱敏、告警触发/恢复、HTTP 窗口与最小样本、任务/预占统计、历史容量上限、后台配置保存失败保留输入及操作页面。与已有管理员 API/界面回归一起执行。

## 私有备份目录的容量汇总

可通过启动参数 `directorySummaryFile:'/run/paperknow-ops/storage.json'` 优先读取 root 生成的数字容量汇总。读取采用不跟随最终符号链接的方式，校验文件为 root 所有、普通文件、组及其他用户不可写、内容最多 64 KiB；只接受规范 UTC 时间和非负有限容量。摘要不含文件名、用户内容、凭据或备份正文。

可信汇总优先于应用进程的目录扫描，不需要开放私有备份目录的读取权限。汇总超过 26 小时会标记为历史值、触发更新超期告警，页面显示每个目录的统计时间；缺少可信汇总时回退到原有有界扫描，并保留不完整标识。监控不会读取或修改 root 的备份文件。

Linux 无法取得 `MemAvailable` 时显示可用内存读数未知，不退回 `MemFree` 触发高占用告警。
