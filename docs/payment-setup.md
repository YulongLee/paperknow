# PaperKnow 支付配置与验收

配置说明更新：2026-10-16。会员订阅、积分购买和套餐购买均接入微信支付与支付宝的统一扫码支付流程，商户参数由管理员在 `/admin.html#payments` 中配置。本文描述已实现的接口与配置边界，不代表任何商户已审核通过、渠道已完成真实收款或商品已上架。

## 当前支持范围

| 渠道 | 当前接入方式 | 商户需开通的能力 |
|---|---|---|
| 微信支付 | API v3 Native 下单，普通商户直连、微信支付公钥模式 | 对应应用和商户的 Native 支付 |
| 支付宝 | 当面付 `alipay.trade.precreate` 预创建交易，生成支付二维码；RSA2 签名与公钥验签 | 对应应用的当面付扫码支付 |

网站展示真实下单返回的二维码，支付结果由服务端异步通知或服务端查单确认，不能通过前端按钮自行标记付款成功。当前没有接入微信 H5、JSAPI、小程序支付、支付宝手机网站跳转、自动续费或自动退款。手机浏览器能打开购买页不代表已支持 H5 / JSAPI 唤起支付。

官方接口说明：[微信 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[微信 API v3 与公钥模式](https://pay.wechatpay.cn/doc/v3/merchant/4012081606)、[支付宝交易预创建](https://developer.alibaba.com/docs/api.htm?apiId=862&docType=4)。商户开通状态及最新平台要求应在各自商户平台核对。

## 渠道开关与用户购买流程

支付配置页面顶部独立控制微信支付、支付宝。商户参数保存完整不等于渠道已经启用；开启对应开关后，收银台才会展示该方式。开关立即保存，关闭保留商户参数和密钥。参数表单中有未保存修改时，须先保存，再切换该渠道。保存参数本身会保留当前启用状态。

会员、积分和套餐页面只负责选择商品与确认金额，不展示支付品牌或提前选择渠道。进入收银台后，仅显示管理员已启用且配置完整的方式：开启一个显示一个，开启两个显示两个，没有可用方式时显示暂停收款。旧链接指定的渠道已关闭时，不自动替用户换选；须主动选择当前可用方式。

渠道开关控制新下单，服务端仍会逐渠道校验。关闭渠道不会自动撤销微信或支付宝已经生成的二维码；原订单继续按历史配置验签、查单及确认结果。

## 先准备服务端配置加密

服务端环境变量仅需要新增 `PK_PAYMENT_CONFIG_KEY`。微信和支付宝的商户参数不写入公开页面、前端脚本或示例环境文件；由管理后台提交并加密保存到支付数据库。

- `PK_PAYMENT_CONFIG_KEY` 必须是**严格 32 字节加密随机数据的标准 Base64 编码**：共 44 个字符，以一个 `=` 结尾。不是任意 32 字符密码，不接受十六进制、Base64URL 或前后带空白的内容。
- 正式环境保存到 `/etc/paperknow/paperknow.env` 等受控的应用环境文件，限制读取权限。模板中的值必须留空。
- 使用 AES-256-GCM 加密商户配置，每个版本独立随机 nonce，配置身份与版本作为关联校验数据；后台查询仅返回公开标识和“已保存”标记，不回显签名私钥、API v3 密钥及验签公钥内容。
- **必须备份此加密密钥，并在恢复数据库时恢复同一密钥。当前没有密钥轮换或重加密迁移工具，不能直接更换或删除该值。** 历史订单会引用原配置版本，丢失或修改密钥会导致历史配置不可解密，影响查单与异步通知处理。
- 数据库备份与密钥备份都必须纳入恢复方案，分开受控保存；不把解密密钥和数据库一起公开打包，不写入 Git、操作截图或聊天记录。
- 回滚应用版本时保持密钥一致，不用旧交易数据库覆盖新产生的订单与权益记录。

没有有效加密密钥时，后台显示未就绪并阻止保存商户参数。未配置渠道、未启用渠道或没有上架商品时，用户不能创建真实购买订单。首次部署不自动开通收款渠道。2026-10-16 用户明确确认的三档积分商品会以固定 SKU 初始化；后续重启不会覆盖管理员改价、下架或其他已保存设置，也不会自动启用支付渠道。

## 微信支付参数

管理员打开“支付配置 → 微信支付”。当前使用微信支付公钥模式，不支持用平台证书配置替代公钥 ID 和公钥。

| 后台字段 | 参数名 | 填写内容 |
|---|---|---|
| 应用 AppID | `appId` | 已绑定商户的微信应用 ID，`wx` 开头；须与实际商户应用关系一致 |
| 商户号 | `merchantId` | 收款商户号，不是应用 ID |
| 商户 API 证书序列号 | `merchantSerial` | 与当前商户 API 私钥对应的商户证书序列号；不是微信支付公钥 ID |
| 商户 API 私钥 | `privateKey` | PEM 格式 RSA 私钥，至少 2048 位；私钥由商户持有 |
| API v3 密钥 | `apiV3Key` | 商户平台配置的 32 位 ASCII 密钥，用于解密通知内容 |
| 微信支付公钥 ID | `platformPublicKeyId` | `PUB_KEY_ID_` 开头的微信支付公钥 ID |
| 微信支付公钥 | `platformPublicKey` | 上述公钥 ID 对应的 PEM 格式 RSA 公钥，用于接口应答与通知验签 |

回调地址为只读配置：

```text
https://paperknow.cn/api/payments/notify/wechat
```

先保持“启用微信支付”关闭，填写并保存参数，再执行“检查已保存配置”。本地检查通过后，结合商户平台的开通状态决定是否启用。微信支付公钥与商户证书属于不同材料，不能互换。共享同一商户号的其他项目须独立核对公钥模式兼容性，不能为了 PaperKnow 调整其他项目的回调或支付逻辑。

## 支付宝参数

管理员打开“支付配置 → 支付宝”。当前接入公钥模式与 RSA2 签名，不支持证书模式或将应用公钥当作支付宝验签公钥。

| 后台字段 | 参数名 | 填写内容 |
|---|---|---|
| 应用 AppID | `appId` | 已开通当面付的支付宝开放平台应用 ID |
| 收款卖家 PID | `sellerId` | 实际收款支付宝商家 UID / PID；须与应用及收款关系一致 |
| 应用私钥 | `privateKey` | 与该应用公钥配对的 PEM 格式 RSA 私钥，至少 2048 位 |
| 支付宝公钥 | `alipayPublicKey` | 支付宝开放平台提供的验签公钥；不是自行生成的应用公钥 |

回调地址为只读配置：

```text
https://paperknow.cn/api/payments/notify/alipay
```

先关闭渠道保存参数并检查，再结合支付宝商户产品开通情况启用。当前使用正式网关，不会因为填入测试应用参数自动切换到沙箱环境。

## 保存、移除和检查

- 两个渠道独立保存；一个渠道保存失败不会代表另一个渠道已经修改。
- 已保存的密钥与验签公钥均不回显。**留空保留旧值**；填写新内容后替换。要删除时必须选择该字段的“移除已保存”选项并保存，空输入框本身不是删除指令。
- 没填齐时可保持渠道关闭，先保存部分配置；启用前必须通过格式与完整性检查。
- `configured` 表示本地参数完整，`ready` 表示渠道已启用且本地配置完整。它们不证明商户签约状态、应用授权或真实收款能力。
- “检查已保存配置”只检查字段完整性、ID 和密钥格式等本地结构，**不向支付平台创建交易、不扣款、不执行真实连通性或收款验证**。先保存修改后才能检查。
- 管理后台只有当前管理员可访问。保存、检查或浏览页面都不应将真实密钥写入操作备注、反馈或日志文本。

## 商品与权益

会员订阅、积分购买和套餐购买均使用相同的微信支付及支付宝渠道配置。会员按有效期记录，积分按整数入账，套餐按服务项和次数独立发放；不会将套餐替换成会员或积分。后台“可售商品”分为三组，均可独立配置和上架。

套餐固定 SKU 为 bundle-rewrite、bundle-reduce、bundle-dual、bundle-junior、bundle-bachelor、bundle-master、bundle-doctor。首次迁移仅添加未上架的参考商品，不启用渠道，不覆盖管理员已修改的商品。上架须填写售价、1–366 天有效期、实际交付说明和 1–20 项服务；每项有唯一规范标识、名称及 1–100000 的整数次数。

套餐支付确认后，订单快照中的服务项、已购次数和有效期保存在独立套餐权益表。当前支持购买发放、对应账户任务消费预占与成功扣减；失败、取消或重启中断会释放预占。原路退款与退款撤回尚未实现。管理员应在实际交付方式和可用服务就绪后上架；只允许将已接通且开启计费的 polish / review / agent 服务配置为可售次数，旧竞品服务键不能直接上架。商品修改只影响未来订单。

初始 `basic`、`advanced`、`premium` 商品均为 `preview`（未上架），不自动使用前端套餐参考价格。会员商品信息由管理员在同页“可售商品”区域逐项保存。科研积分的 `credits-200`、`credits-500`、`credits-1000` 则按用户确认金额初始化为可售商品（2000 / 5000 / 10000 分），收款仍受渠道开关和配置完整性限制。

上架前必须填写真实商品名称、实际售价、1–366 个整数天的会员有效期，以及当前确实能够交付的权益说明 `description`。后台售价使用元输入，按十进制规则精确转成整数分；服务端按商品记录确认金额，不能接受浏览器自报价格。未上架时价格和有效期可以留空。

当前实现的是**付款订单、会员权益、科研积分充值账本与套餐已购权益**：会员支付确认后记录会员起止时间；积分支付确认后按订单快照的整数积分数量入账；套餐支付确认后按订单快照记录服务项、次数和起止时间。三种履约与订单状态更新位于同一数据库事务，重复通知不会重复发放；金额、应用与商户身份均由服务端核验。积分账本只追加，充值与消费事件均由服务端记账，前端不能修改余额。任务计费现支持学术润色、导师意见修改、科研智能助手；没有自动解锁未开放的 AI 服务、短信或下载权限。退款冲正、积分失效政策与转赠仍未提供。不能把这些未实现能力写入收费承诺。当前没有自动退款与退款后权益撤回流程，需另行开发并验收，不能在前端直接把订单修改为“已退款”。

商品上架前应核对说明与实际交付，未准备好的商品保持未上架。修改商品影响后续订单；已创建订单使用创建时保存的价格及权益快照。

## 正式收款前验收

1. 确认 HTTPS 可用，支付平台能向两个回调地址发送通知；反向代理不要将其重写到首页或拦截为登录页面。不修改同机其他服务路由。
2. 确认服务端系统时间准确，商户应用、收款账户、签名材料及平台公钥属于同一套正式配置。
3. 关闭渠道完成参数录入，执行本地检查；参数不完整时不得启用。
4. 配置可交付商品的真实价格、有效期与权益说明。受控测试期间只开放已确认可交付的商品。
5. 启用待验证的渠道，使用一笔受控真实交易，核对平台交易号、商户收款记录、网站订单金额与“已支付”状态，以及账户的会员权益起止时间或积分到账数量与流水。
6. 核对重复通知不会重复授予权益；重新打开订单并查询支付结果，不以二维码出现或点击“已完成支付”作为收款凭据。
7. 如应用配置、商户审核、异步通知或商品交付存在问题，停止新收款并排查；不要改写订单伪造成功。退款需求须在商户平台与内部记录核对后另行处理，当前没有网站自动退款入口。只有服务接通并在后台设置为按权益计费，相关商品才接受收款；未准备好的消费服务不应列入可用承诺。

自动化用例使用模拟通道及测试签名验证代码行为，不能代替上述真实商户交易验收。本文件不记录任何真实商户密钥、加密密钥或银行卡信息。

## 商业化消费闭环（2026-10-16）

管理后台「商品与计费」先配置三项真实任务的免费、按权益计费或暂停状态及每次积分。初始全为免费，发布代码不会自动打开收费。任务按固定每次计价；正文和文件限制仍由任务接口执行，不以模型 Token 数临时改变用户已确认的积分。

付费任务固定按有效会员次数、套餐次数、积分的优先次序报价。会员和套餐为本笔订单有效期内的服务总次数，不按月重置；同方案续购顺延时间，不同方案独立，不自动折算升级。选择权益时优先使用较早到期的可用订单。免费任务不消耗付费权益。

报价有效 5 分钟，保存用户、任务类型、规则版本、金额及具体权益来源。提交前由用户明确确认；提交时在同一事务内创建任务并预占。成功结果、模型用量和消费结算位于同一事务；失败、用户取消、管理员取消、重启中断均释放预占。释放使可用积分恢复，不向余额重复加钱。失败重试需要新报价与新确认；相同创建请求的幂等标识防止重复创建及扣费。

后台商品发布、任务提交和支付创建均独立检查。积分只在至少一个真实付费服务可用时接受充值；会员和套餐每个服务项必须对应已接通且启用计费的支持键。不更改既有商户开关、商品售价和订单快照。历史未支付订单仍可按原签名通知完成支付核验，不受新商品销售门槛影响。

排查「配置微信后仍不能充值」时，分别核对支付渠道、服务计价与商品可交付状态。`ready` 只表示渠道已启用且本地参数完整，不表示已完成真实支付。没有任何按权益计费的服务时，商品返回 `credit_pricing_missing`；已经计价但服务不可用时返回 `credit_services_unavailable`。后台顶部会解释当前收款条件。保存服务计价后，同步刷新商品可售提示，保留其他未保存的参数和商品草稿。

项目负责人于 2026-10-16 确认：当前注册的收费任务暂按 **10 积分/次**，可在后台逐项改价；未接通的服务继续禁止付费提交。此定价通过线上管理配置保存，不作为新部署的默认收费开关。三档充值维持 200 / 500 / 1000 积分对应 ¥20 / ¥50 / ¥100。

尚未完成的商业运营能力：原路退款、退款后积分与次数冲正、自动账单对账、订单关联售后与开票管理、优惠码及自动续费。这些不能写入已经完成的对外承诺。真实商户扫码、回调和到账仍须人工受控验收；自动化模拟网关不代表真实收款成功。
