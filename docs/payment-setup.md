# PaperKnow 支付配置与验收

配置说明更新：2026-10-15。当前接入微信支付与支付宝的扫码支付流程，商户参数由管理员在 `/admin.html#payments` 中配置。本文描述已实现的接口与配置边界，不代表任何商户已审核通过、渠道已完成真实收款或商品已上架。

## 当前支持范围

| 渠道 | 当前接入方式 | 商户需开通的能力 |
|---|---|---|
| 微信支付 | API v3 Native 下单，普通商户直连、微信支付公钥模式 | 对应应用和商户的 Native 支付 |
| 支付宝 | 当面付 `alipay.trade.precreate` 预创建交易，生成支付二维码；RSA2 签名与公钥验签 | 对应应用的当面付扫码支付 |

网站展示真实下单返回的二维码，支付结果由服务端异步通知或服务端查单确认，不能通过前端按钮自行标记付款成功。当前没有接入微信 H5、JSAPI、小程序支付、支付宝手机网站跳转、自动续费或自动退款。手机浏览器能打开购买页不代表已支持 H5 / JSAPI 唤起支付。

官方接口说明：[微信 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[微信 API v3 与公钥模式](https://pay.wechatpay.cn/doc/v3/merchant/4012081606)、[支付宝交易预创建](https://developer.alibaba.com/docs/api.htm?apiId=862&docType=4)。商户开通状态及最新平台要求应在各自商户平台核对。

## 先准备服务端配置加密

服务端环境变量仅需要新增 `PK_PAYMENT_CONFIG_KEY`。微信和支付宝的商户参数不写入公开页面、前端脚本或示例环境文件；由管理后台提交并加密保存到支付数据库。

- `PK_PAYMENT_CONFIG_KEY` 必须是**严格 32 字节加密随机数据的标准 Base64 编码**：共 44 个字符，以一个 `=` 结尾。不是任意 32 字符密码，不接受十六进制、Base64URL 或前后带空白的内容。
- 正式环境保存到 `/etc/paperknow/paperknow.env` 等受控的应用环境文件，限制读取权限。模板中的值必须留空。
- 使用 AES-256-GCM 加密商户配置，每个版本独立随机 nonce，配置身份与版本作为关联校验数据；后台查询仅返回公开标识和“已保存”标记，不回显签名私钥、API v3 密钥及验签公钥内容。
- **必须备份此加密密钥，并在恢复数据库时恢复同一密钥。当前没有密钥轮换或重加密迁移工具，不能直接更换或删除该值。** 历史订单会引用原配置版本，丢失或修改密钥会导致历史配置不可解密，影响查单与异步通知处理。
- 数据库备份与密钥备份都必须纳入恢复方案，分开受控保存；不把解密密钥和数据库一起公开打包，不写入 Git、操作截图或聊天记录。
- 回滚应用版本时保持密钥一致，不用旧交易数据库覆盖新产生的订单与权益记录。

没有有效加密密钥时，后台显示未就绪并阻止保存商户参数。未配置渠道、未启用渠道或没有上架商品时，用户不能创建真实购买订单。首次部署不自动开通收款；后续重启也不会代替管理员开通渠道或上架商品。

## 微信支付参数

管理员打开“支付配置 → 微信支付”。当前使用微信支付公钥模式，不支持用平台证书配置替代公钥 ID 和公钥。

| 后台字段 | 参数名 | 填写内容 |
|---|---|---|
| 应用 AppID | `appId` | 已绑定商户的微信应用 ID，`wx` 开头；须与实际商户应用关系一致 |
| 商户号 | `merchantId` | 收款商户号，不是应用 ID |
| 商户 API 证书序列号 | `merchantSerial` | 与当前商户 API 私钥对应的商户证书序列号；不是微信支付公钥 ID |
| 商户 API 私钥 | `privateKey` | PEM 格式 RSA 私钥，至少 2048 位；私钥由商户持有 |
| API v3 密钥 | `apiV3Key` | 商户平台配置的 32 位 ASCII 密钥，用于解密通知内容 |
| 微信支付公钥 ID | `platformPublicKeyId` | `PUB_KEY_ID_` 开头的微信支付公钥 ID |
| 微信支付公钥 | `platformPublicKey` | 上述公钥 ID 对应的 PEM 格式 RSA 公钥，用于接口应答与通知验签 |

回调地址为只读配置：

```text
https://paperknow.cn/api/payments/notify/wechat
```

先保持“启用微信支付”关闭，填写并保存参数，再执行“检查已保存配置”。本地检查通过后，结合商户平台的开通状态决定是否启用。微信支付公钥与商户证书属于不同材料，不能互换。共享同一商户号的其他项目须独立核对公钥模式兼容性，不能为了 PaperKnow 调整其他项目的回调或支付逻辑。

## 支付宝参数

管理员打开“支付配置 → 支付宝”。当前接入公钥模式与 RSA2 签名，不支持证书模式或将应用公钥当作支付宝验签公钥。

| 后台字段 | 参数名 | 填写内容 |
|---|---|---|
| 应用 AppID | `appId` | 已开通当面付的支付宝开放平台应用 ID |
| 收款卖家 PID | `sellerId` | 实际收款支付宝商家 UID / PID；须与应用及收款关系一致 |
| 应用私钥 | `privateKey` | 与该应用公钥配对的 PEM 格式 RSA 私钥，至少 2048 位 |
| 支付宝公钥 | `alipayPublicKey` | 支付宝开放平台提供的验签公钥；不是自行生成的应用公钥 |

回调地址为只读配置：

```text
https://paperknow.cn/api/payments/notify/alipay
```

先关闭渠道保存参数并检查，再结合支付宝商户产品开通情况启用。当前使用正式网关，不会因为填入测试应用参数自动切换到沙箱环境。

## 保存、移除和检查

- 两个渠道独立保存；一个渠道保存失败不会代表另一个渠道已经修改。
- 已保存的密钥与验签公钥均不回显。**留空保留旧值**；填写新内容后替换。要删除时必须选择该字段的“移除已保存”选项并保存，空输入框本身不是删除指令。
- 没填齐时可保持渠道关闭，先保存部分配置；启用前必须通过格式与完整性检查。
- `configured` 表示本地参数完整，`ready` 表示渠道已启用且本地配置完整。它们不证明商户签约状态、应用授权或真实收款能力。
- “检查已保存配置”只检查字段完整性、ID 和密钥格式等本地结构，**不向支付平台创建交易、不扣款、不执行真实连通性或收款验证**。先保存修改后才能检查。
- 管理后台只有当前管理员可访问。保存、检查或浏览页面都不应将真实密钥写入操作备注、反馈或日志文本。

## 商品与权益

初始 `basic`、`advanced`、`premium` 商品均为 `preview`（未上架），不自动使用前端套餐参考价格。商品信息由管理员在同页“可售商品”区域逐项保存。

上架前必须填写真实商品名称、实际售价、1–366 个整数天的会员有效期，以及当前确实能够交付的权益说明 `description`。后台售价使用元输入，按十进制规则精确转成整数分；服务端按商品记录确认金额，不能接受浏览器自报价格。未上架时价格和有效期可以留空。

当前实现的是**付款订单与会员权益账本**：支付确认后记录对应商品的会员起止时间。没有自动解锁尚未开放的 AI 服务、短信额度、点数、下载权限或其他未实现能力；不能把这些能力写入收费承诺。当前没有自动退款与退款后权益撤回流程，需另行开发并验收，不能在前端直接把订单修改为“已退款”。

商品上架前应核对说明与实际交付，未准备好的商品保持未上架。修改商品影响后续订单；已创建订单使用创建时保存的价格及权益快照。

## 正式收款前验收

1. 确认 HTTPS 可用，支付平台能向两个回调地址发送通知；反向代理不要将其重写到首页或拦截为登录页面。不修改同机其他服务路由。
2. 确认服务端系统时间准确，商户应用、收款账户、签名材料及平台公钥属于同一套正式配置。
3. 关闭渠道完成参数录入，执行本地检查；参数不完整时不得启用。
4. 配置可交付商品的真实价格、有效期与权益说明。受控测试期间只开放已确认可交付的商品。
5. 启用待验证的渠道，使用一笔受控真实交易，核对平台交易号、商户收款记录、网站订单金额与“已支付”状态，以及账户的会员权益起止时间。
6. 核对重复通知不会重复授予权益；重新打开订单并查询支付结果，不以二维码出现或点击“已完成支付”作为收款凭据。
7. 如应用配置、商户审核、异步通知或商品交付存在问题，停止新收款并排查；不要改写订单伪造成功。退款需求须在商户平台与内部记录核对后另行处理，当前没有网站自动退款入口。

自动化用例使用模拟通道及测试签名验证代码行为，不能代替上述真实商户交易验收。本文件不记录任何真实商户密钥、加密密钥或银行卡信息。
