# 专用备份桶拒绝策略：只读评估

**这不是可直接部署的桶策略。** 现有账号的 RAM 策略只读盘点显示，有 3 份系统策略包含无条件、广泛资源范围的 OSS 对象数据操作；生产服务还持有该云账号根身份。私有 ACL 和阻止公共访问不能排除已授权的这些身份。当前无法证明在不影响恢复的情况下对新桶完成隔离，因此尚未创建桶或测试真实云资源。

阿里云文档说明显式 Deny 优先于 Allow；桶策略以 `Principal: ["*"]` 配合条件时可能包含桶拥有者。官方示例使用 `acs:AccessId` 配合 `StringNotLike` 限制长效或临时凭据。理论上可针对备份桶的对象操作设置拒绝：除专用备份与恢复凭据外，拒绝其他 AccessKey 操作；管理桶策略的操作不在该拒绝动作内，从而保留独立管理员的策略恢复路径。候选还需要最小权限的 RAM Allow，因为不匹配 Deny 本身不会授权。

但此方案尚不能部署：需要验证 `acs:AccessId` 对根账号、RAM 用户、STS 会话、控制台、匿名请求和缺失条件的实际取值；覆盖复制、分片、对象版本、读取和删除等所有相关 API；核对桶策略对管理操作的例外；验证密钥轮换、恢复凭据丢失与服务端审计。授权范围、优先级或管理恢复路径一旦假设错误，可能暴露数据或锁住桶。独立云账号降低同账号根凭据和其他 RAM 策略的耦合，但也须核查目标账号访问策略和安全恢复。两种方案都需要实际受控验证。

`tests/oss-bucket-policy-model.test.mjs` 只用虚构身份模拟基本的“明确拒绝优先、例外不自动授予权限”；它不是阿里云策略模拟器，也没有覆盖缺失上下文或其他 API，**通过不等于云策略正确或可恢复**。正式验证应先通过云方策略模拟与隔离合成环境，确认管理身份可以修改/移除桶策略、备份身份可正常读写、现有生产和其他身份不能读写、轮换及故障恢复均可用；通过前不向任何桶上传用户数据。

参考：[阿里云桶策略](https://www.alibabacloud.com/help/en/oss/user-guide/oss-bucket-policy/)、[授权语法和条件](https://www.alibabacloud.com/help/en/oss/user-guide/authorization-syntax-and-elements)。
