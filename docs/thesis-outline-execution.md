# 毕业论文提纲执行

提纲任务使用提交时冻结的 Agent 配置版本。后台允许的交互轮次适用于材料读取、完整候选提交和校验后修正的整个执行过程，不再另行压缩到 3 轮。仍遵守后台 1～12 轮的允许范围，不能通过切换当前配置改变已经排队任务的配置。

单次保护与账户积分分开：积分或套餐授权任务结算，不会解除模型的执行资源限制。提纲默认合计处理量上限为 200,000 tokens；后台已保存的单次模型费用、超时和输出上限仍然生效。任务失败释放原预占，完整候选校验通过并保存后才结算一次。

例如分三轮读取材料后，第四轮提交提纲，发现结构问题再用第五轮修正；后台允许 12 轮时，这个流程应在原任务中完成，不应在第三轮结束时失败。服务不自动重新提交已经失败的历史收费任务，不覆盖既有提纲。

回归覆盖：

- 冻结配置允许 1、5、12 轮时，提纲执行使用对应上限；当前配置的后续改动不影响原任务。
- 真实 SDK 进程连接合成提供方，三轮读取、一次拒绝、一次修正后完成，实际五次模拟提供方响应的用量累加正确。
- 整个自动修正过程只产生一个权益预占、一份结果和一次结算；执行失败或取消仍释放预占。
- 既有处理量、费用、输出、取消、版本校验和账户隔离检查继续适用。

上述回归只使用合成资料和模拟提供方，不消耗生产模型费用或用户账户积分。
