# PaperKnow 全站检查记录

检查日期：2026-10-06。对象：当前本地版本、官网、研究工作台和本地论文比对报告。

## 结论

目前可以作为本地体验版继续测试，界面分类和主要内容管理流程已形成。但尚不具备面向真实付费用户运营的完整服务能力：预览服务器只提供静态文件，正式账户、数据库、云端文件、任务队列、在线 AI、开放学术检索、支付及工单服务尚未接入。视觉完成度不能代替这些能力的验收。

本次检查修复可复现的数据丢失、入口不一致和备份遗漏问题。83 项自动化测试通过；不代表所有浏览器、复杂论文文件和生产安全场景已验证。

- 浏览器检查工作台 17 个主要路由：概览、项目、成果、任务、写作、文献、修改、检测、PPT、科研工具、格式排版、更多工具、会员、设置、帮助、账户和订单。
- 检查官网功能入口、手机菜单、功能状态弹窗及旧版研读入口；旧入口现在打开文献工作区。

## 已修复的问题

| 优先级 | 问题与影响 | 修复结果 |
| --- | --- | --- |
| P1 | 论文写作和部分结构模板切换路由时静默丢失输入 | 增加离开选择及刷新保护；解析中阻止离开；校验/保存失败保留编辑 |
| P1 | 文献笔记切换到另一条笔记或编辑文献资料时可能覆盖未保存输入 | 笔记离开可保存，切换编辑对象前需保存当前笔记 |
| P1 | 其他窗口更新存储时，修改稿页面可能被重新挂载而丢失当前输入 | 修改稿有未保存编辑时不因存储事件重新挂载 |
| P1 | 工作空间备份遗漏 IndexedDB 中单独保存的查重对照材料 | 备份纳入对照材料；与报告共用写事务；失败回滚；兼容不含材料的旧备份 |
| P1 | 官网修改昵称会清除学段、专业与研究方向等账户字段 | 只更新昵称并保留现有资料；研究方向也纳入个人资料恢复 |
| P2 | 查重、文献研读、投稿等快捷入口仍进入旧流程 | 更新主要入口，兼容旧工具 URL；项目查重入口传递项目关联 |
| P2 | 官网、上传说明仍称新版排版/PPT/研读只是清单或提纲 | 说明更新为实际能力与限制，保留在线服务尚未接入的提示 |
| P2 | 部分草稿编号依赖时间，快速创建可能冲突 | 新建写作和模板草稿使用 UUID；原记录仍可打开 |
| P2 | 旧查重页面来源年份未统一作为纯文本转义 | 将四处年份展示统一转义，避免将输入作为页面标记解析 |

## 商业化下一步，按优先级推进

### 第一阶段：先完成数据和身份基础

1. 接入真实登录、会话、用户隔离、账户资料、安全设置与退出机制。当前昵称不等于身份认证。
2. 建立项目、成果、版本、文献、报告和来源证据的统一数据库；文件存储与访问权限由服务端控制。
3. 加入自动草稿保存、保存失败恢复、跨窗口冲突检测与多设备同步。当前多数编辑仍需主动保存；本次离开提示不是自动保存。
4. 为所有导入、项目/资料弹窗统一补充关闭保护；文献导入弹窗、检测输入等尚未覆盖所有闲置输入的离开场景。
5. 当前部分读取方法会在 JSON 损坏后回退为空列表。应统一区分“确实为空 / 读取失败”，阻止覆盖损坏数据，并提供原始数据导出。
6. 保留备份恢复预览及失败恢复能力。localStorage 与 IndexedDB 不能在崩溃/断电时提供跨系统原子保证；云端应提供事务、版本和恢复记录。

验收：两位真实测试用户数据相互隔离；换设备可恢复；断网、存储失败和冲突时不会误报保存成功或覆盖内容。

### 第二阶段：完成论文服务闭环

1. 建立文档解析和异步任务队列，提供真实状态、失败原因、重试/取消和任务结果，页面刷新后任务仍可追踪。
2. 接入实际 AI 服务，记录调用、限额和失败；改写、研读、翻译等结果始终可核对原文与来源。
3. 论文查重接入授权的候选检索和可用正文。Crossref 用于元数据和 DOI 核验；开放全文需核对许可与获取范围。
4. 当前算法是本地连续文本匹配，不包含全网候选检索或语义服务。上线前应使用中文/英文真实测试集验证查全率、误报、引用排除、区间去重与数据源覆盖。
5. 来源不可获取或没有命中时，不生成推测的重复率；报告保持数据库覆盖说明，与学校平台的结果明确区分。
6. 检测 → 对照来源 → 手动/AI 修改 → 新版本检测形成闭环，保留原稿、修改记录和每次检测的证据快照。

验收：每个高亮片段可定位实际候选文本；计算可复现；不依赖 LLM 输出最终相似率；服务错误和检索不足可见。

### 第三阶段：收费和运营

1. 根据真实服务成本制定套餐、用量单位、扣费时机、失败返还和订单状态；付费回调和重复请求需保证幂等。
2. 会员页展示真实权益、账单和消耗；当前本地数量不能作为 AI 调用量或在线额度。
3. 帮助反馈接入工单、提交状态与历史回复；当前仅保存/导出本地反馈，没有实际发送渠道。
4. 上线后持续收集用户在哪一步退出、解析失败、保存失败、导出失败和返工情况，再优化转化。当前没有验证过的用户转化数据。

验收：完整测试成功支付、重复回调、取消、失败服务、返还及权益到期；客服能查询真实任务与订单。

### 第四阶段：体验与工程质量

- 统一功能状态标签和旧路由兼容策略，避免重复工具入口造成认知负担。
- 手机编辑长论文与桌面多栏报告分别设计；手机导航抽屉关闭时应使用 inert/可见性管理，避免键盘与辅助工具进入屏幕外导航。本次布局测试未覆盖屏幕阅读器完整操作。
- 为复杂 Word、PDF 公式/表格、扫描件、中文字体、长 PPT 和低性能设备建立样本回归。当前无 OCR，浏览器正文预览不能替代 Word/PowerPoint 最终文件核对。
- CI 执行语法、构建、单元测试与关键浏览器流程；补充加载失败、下载文件内容、无障碍及性能检查。
- 正式部署配置 HTTPS、访问控制、资源安全策略、日志和监控；当前服务器仅绑定 127.0.0.1，属于本地预览。

## 检查限制

- 依赖漏洞扫描未完成：配置的镜像 registry 不提供安全公告接口，改用 npm 官方 registry 后又遇到证书主机名校验失败。未跳过 TLS 校验，不将其报告为“无漏洞”。需要在可信网络/CI 中重新扫描。
- 本次不是渗透测试、跨设备兼容认证或性能压测；没有生产后端可进行身份隔离、支付回调、外部检索、AI 并发和队列恢复测试。
- 文件处理与导出主要沿用已有自动化样本，并新增本次缺陷回归。没有逐份验证所有用户论文，也不能承诺任意复杂文件保持排版完整。
- 未清理用户已有项目、成果、文献或报告。浏览器复现只输入临时内容后放弃；持久化与恢复测试使用独立模拟存储。
