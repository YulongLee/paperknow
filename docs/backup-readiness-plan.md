# PaperKnow 独立备份：实施前检查

本文记录人工实施方案，**不代表线上备份或灾难恢复已经启用**。真实用户数据的备份、存储配置和恢复演练须在下列条件落实并通过审阅后进行。实现和安全边界见 `oss-offline-snapshot.md`、`oss-cloud-encrypted-backup.md`。

## 已核查的现状

- 生产对象存储位于上海地域，源桶为私有标准存储；生产数据库约 17 MB。备份工具尚未对真实数据或目标云桶进行验收。
- 现有生产存储凭据对应云账号根身份，并非独立的受限 RAM 身份；不要将该凭据直接用于备份。生产身份的最小权限化及密钥轮换应单独制定回滚方案，不能未经验证直接修改运行服务。
- 只读查询显示该地域 KMS 尚未启用。Mac 系统盘启用了 FileVault，但本机钥匙串只是单设备保存方式，无法证明设备丢失后的可恢复性。线上服务器的现有磁盘布局未显示独立加密卷。

## 必须先完成的条件

1. **建立独立的密钥恢复路径。** 使用与备份分离的受控密钥管理服务，或由负责人员在受控的独立密码保险库及另一安全位置保存同一随机密钥；明确授权人员、恢复步骤和密钥版本。Mac 钥匙串可以作为其中一份，不能仅依赖这一台设备。不得通过聊天、命令参数、Git 或日志传输密钥。先用合成材料从另一受控环境完成密钥获取及解密演练。服务器和该 Mac 均不可用时，授权人员仍应能够恢复密钥。
2. **建立专用存储与最小权限。** 另建单独的私有备份桶，开启公共访问阻断，核验 ACL、桶策略、账号级设置、对象版本状态以及跨账号访问；不得修改源桶。为源读取和目标备份分别配置专用受限身份：源身份只允许读取需要的源前缀，目标身份只允许备份工具需要的读取、写入和桶配置只读查询，不授予源写入、目标删除或管理其他桶的权限。以实际身份执行允许与拒绝的权限测试。由于工具要求禁止覆盖，当前目标桶不能启用或暂停版本控制；对象锁、保留策略与此限制的兼容性须另行设计和验证。
3. **确认隔离的明文工作空间。** 临时数据库快照、对象副本与恢复文件均含明文，必须放在经过验证的加密卷，访问权限仅限运维人员。现有 FileVault Mac 可以作为人工演练候选，但必须核查用户会话、空间及权限，并明确本机失效时的替代恢复环境。不得以普通目录权限代替磁盘加密。
4. **控制一致性并验证恢复。** 在可控窗口生成一致的 SQLite 快照，先检查数据库和源对象关联；同步进行的删除、覆盖或上传可能造成备份失败。真实备份完成后，从新环境解密到独立目录，先通过文件与数据库校验，再启动隔离应用核验账号、项目、任务和文件下载，并记录恢复时间。不向生产环境写回或覆盖任何文件。
5. **确定运维责任。** 指定负责人、备份频率、失败告警、定期恢复演练、容量及费用预算。当前工具没有自动调度、自动清理、保留期限或失败告警。不得在未批准保留策略前自动删除备份；异常中断可能遗留加密孤儿对象，须人工核对。

## 当前限制

工具对单个数据库快照限制为 100 MiB、单个对象限制为 20 MiB；超过时会失败，需要在到达上限前扩容方案和告警。快照不包含环境配置、云资源配置、对象历史版本或无索引孤儿对象；软件版本、恢复配置和密钥版本需要另行安全保管。对象加密、模拟测试及成功上传均不能单独证明完整灾备能力。

备份桶会产生存储、请求与可能的流量费用；KMS 若单独启用也可能产生费用。具体金额取决于地域、容量、请求、计费方式和服务开通情况，应在云控制台确认，不能以当前测试费用代替长期预算。
