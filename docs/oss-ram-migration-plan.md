# 生产 OSS 身份隔离：待审核切换方案

此文件是准备方案，不代表已创建账号、变更权限或切换服务。现有生产服务的 OSS 凭据经 STS 只读检查为云账号根身份。同账号下新建私有备份桶并不能阻止持有该根凭据的生产服务访问备份。切换到仅限源桶的身份后，仍需另行核验备份桶的 RAM 授权及桶策略，才能证明生产服务没有备份桶访问权。

只读盘点中，当前账号可列出 1 个 RAM 用户、16 个角色，名称中均无 PaperKnow 标识；这不能证明这些身份的用途或授权范围，也不能证明不存在其他可用云账号。不得复用用途不明、属于其他业务的身份；建议新建专用身份。若使用不同阿里云账号存放备份，仍需分别核查其可信来源和策略。

## 最小能力及候选策略

已核查 `backend/storage.mjs`：原件和成果需向 `paperknow/users/…/originals/` 与 `paperknow/users/…/exports/` 上传、读取、删除对象，上传时要求对象 private ACL；存储健康检查在 `paperknow/_health/` 下写入、读取、删除合成文件。PDF 翻译生成签名 GET 地址，依赖该身份对目标源对象的读取权限。代码未显示需要列举整个桶、管理桶配置或访问其他桶。

候选 RAM 策略如下，实际应用前须核对地域、前缀、对象 ACL 操作和云控制台策略验证结果；不要直接将示例作为已验证策略。此策略有意允许源前缀内删除，因为产品的文件删除和失败清理需要该能力；应仅发给生产服务专用身份，保护其凭据。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:GetObject", "oss:PutObject", "oss:DeleteObject", "oss:PutObjectAcl"],
      "Resource": ["acs:oss:*:*:paperknow-production/paperknow/users/*", "acs:oss:*:*:paperknow-production/paperknow/_health/*"]
    }
  ]
}
```

不要授权备份桶、`oss:*`、全账号存储操作、桶策略管理或列举其他桶。若实际 SDK 行为或第三方集成需要额外权限，先查明具体操作和资源，再最小化调整；不能通过全权限解决测试失败。

## 操作准备与验证

1. 明确责任人、维护时间、回滚负责人和系统实例拓扑。确认现有生产配置文件的私有备份及回滚方式，确保凭据仅由受限运维系统保存，不记录到日志、命令行或聊天；不要删除或停用根凭据，否则可能影响其他业务。
2. 仅为 PaperKnow 服务创建专用 RAM 身份和受限策略，妥善注入新密钥。先以独立的只读测试程序验证其能访问预先选定的合成对象，不能读取源前缀以外的对象，不能读取备份桶、列举其他桶或修改桶策略。不得把凭据权限拒绝误判成文件不存在。
3. 经授权在源桶专用测试前缀写入一个不含用户数据、随机命名的合成对象，验证带 private ACL 的上传、读取内容与哈希、签名 GET、删除和删除后状态；同时验证目标备份桶访问明确返回授权拒绝。测试对象须有明确归属和清理记录，不能批量清理或接触用户文件。运行完整应用的隔离环境测试以涵盖原件、成果、翻译签名和健康检查。
4. 确认旧实例仍能工作、新凭据测试全部通过后，采用受控配置发布替换仅该服务使用的 OSS 凭据。单实例 systemd 重启可能造成短暂中断，不能保证无中断；若具备多实例和负载均衡，应先使用隔离流量的健康新实例，再逐步切换。不要在生产库上启动可能执行任务的影子实例。
5. 切换后监控上传、下载、删除、签名 URL、任务与错误率，确认现有文件可读及新文件完整。老身份签发的 URL 可能仍在有效期内；当前代码的有效期最长 900 秒。根凭据不应因这次变更被立即停用，尤其可能服务于其他应用。
6. 若验证异常，按事先准备的受限配置备份恢复原服务配置，并确认服务恢复及文件读写；记录失败和后续修复。回滚不会撤销已生成的 URL 或清理用户数据。只有确认服务稳定、其他业务与依赖全部核对后，才另行安排根凭据风险处置。

实际策略、授权拒绝测试、配置发布及业务验证都尚未执行。用户数据备份也尚未运行；不得将这份计划视为线上权限隔离完成。
